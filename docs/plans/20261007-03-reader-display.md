### 目的・背景

ローカルの EPUB を選び、縦スクロールをなるべく使わずに読む体験を作る。ユーザーが承認した画面に沿って、本文をウィンドウに収まるページへ分割し、前後ボタンと左右キーで読む。

現在は Rust の内容取得基盤があり、React の画面は初期テンプレートのまま。OS のファイル選択、アプリとの連携、本文の表示・改ページは未実装である。表示の幾何情報を扱えない jsdom のテストだけでは、文字・ルビ・画像が切れないことを確認できないため、実ブラウザと Windows の確認を分けて計画する。

### 問題・解決方法

- 採用案：Windows の標準ファイル選択を Tauri 公式の `tauri-plugin-dialog` から呼び出す。任意のパス入力をユーザーに求めず、OS の慣れた操作を利用するため。Rust 側から利用し、JavaScript 用の dialog パッケージは追加しない。
- 採用案：書籍の状態とファイル読み取りを Rust に置き、React は書籍情報・章本文・状態を受け取る。書籍内の画像・CSS は専用のリソースURLから必要時に取得し、全リソースを JSON で毎回送らない。
- 採用案：ブラウザの CSS 段組みを固定高さ・横方向の連続ページとして利用する。文字組みとルビの描画をブラウザに任せ、独自の組版エンジンを作らない。
- 採用案：本文をアプリの操作部から分離した iframe に表示する。アプリが用意する文書に XHTML の本文と書籍内CSSを組み込み、書籍内のスクリプト・外部通信・フォーム・埋め込みフレームは許可しない。
- 採用案：再配置前に本文中の位置を保持し、再配置後にその位置を含むページへ戻る。ページ番号や移動距離だけを保持すると、画面サイズの変更で読みかけの場所が変わるため。
- 棄却：縦スクロールを主な読み方とする。ユーザーの希望と異なるため。
- 棄却：文字数だけでページを区切る。フォント、ルビ、画像、表示幅により実際の高さが変わり、欠落や重なりが生じるため。
- 保留：EPUB.js 等の追加の描画ライブラリ。まず既存の解析結果とブラウザの組版で必要な範囲を検証する。追加が必要になった場合は理由・範囲を提示して承認を得る。

### 完了条件（DoD）

#### 単位3A：ファイル選択・書籍提供

- アプリのコマンドから標準ファイル選択を開き、選択した EPUB を既存の `Book` で読み込める。キャンセルと読み込み失敗を区別する。
- タイトル・読み順・目次と、後続の章取得に使う書籍識別子を返す。まず最初の主たる章を表示するための本文取得を提供する。
- 別の書籍を正常に開いた場合は識別子を切り替え、古い書籍への要求を新しい書籍の内容で応答しない。キャンセル時は現在の書籍を維持する。
- 本文・画像・CSS の取得を提供し、読み取り不能・破損・非対応・リソース欠落を既存の分類で返す。
- 書籍の manifest に属するリソースだけを提供し、OS の任意のファイルは公開しない。アーカイブ外へのパス、未知の書籍識別子、期限切れの要求を拒否する。
- ファイル選択・連携境界を除く状態遷移、書籍切り替え、本文取得、リソース応答を Rust の自動テストで検証する。
- `cargo check`・`cargo test` と、既存のフロントエンドのテスト・ビルドが成功する。
- 利用可能な環境で実アプリのコマンド・リソースURLを確認し、Windows 固有の URL 形式と標準ダイアログは Windows で確認する。未実施なら、この単位を実機検証済みとしない。

#### 単位3B：ページ分割・表示部品

- 章の本文を画面の高さに合わせた横方向のページに分割し、指定したページだけを表示する。本文領域に縦スクロールを必要としない。
- XHTML の見出し・段落・標準の `ruby`・`rt` と書籍内の PNG・JPEG・GIF を表示できる。長い章・ルビの多い章・大きな画像で本文の欠落やページ間の重なりがないことを確認する。
- 大きな画像は縦横比を保ち、本文領域の幅と高さに収める。画像の読み込み後・フォントの準備後にページ数を確定する。取得失敗は隠さず呼び出し側へ通知する。
- 書籍内CSSの文字装飾・見出し・段落等を適用し、本文のサイズ・段組み・横書き方向・画像の上限・明暗テーマは読書用スタイルを優先する。書籍内CSS全仕様の互換性は保証範囲に含めない。
- ウィンドウのサイズ変更後も、直前のページ先頭の本文位置を含むページへ戻る。文字のない画像ページでも対象要素を位置として保持する。
- 文書中のスクリプト、イベント属性、外部CSS・画像・フォント・通信、フォーム送信、埋め込みフレーム、外部ページへの遷移を無効化する。本文からアプリのコマンドを呼べないことを確認する。
- ページ数・境界・位置保持のロジックは単体テスト、実際の文字組みとリソース表示は Playwright の Chromium で検証する。実ブラウザの計測結果を固定値のモックで置き換えない。
- 明色・暗色、800×600・1280×800 の表示領域を含めて検証する。大きい画面から小さい画面への変更でも位置を保持する。
- `bun --no-env-file run test`・`bun --no-env-file run build` とブラウザテストが成功する。ブラウザ上の成功を Windows の WebView2 の成功とは扱わない。

#### 単位3C：読書画面への接続

- 初期画面を承認済みデザインの読書画面に置き換え、「書籍を開く」から選択・タイトル・最初の章の本文表示までつながる。
- 未選択・読み込み中・成功・失敗を区別する。読み込み中は重複操作を防ぐ。キャンセル時は現在の画面を維持する。
- 前後ボタンと左右キーで章内のページを移動し、先頭・末尾では範囲外へ進まない。ページ位置は「現在ページ / この章のページ数」とし、書籍全体のページ数として表示しない。
- 本文iframeにフォーカスがある場合も左右キーで移動する。入力欄・修飾キー操作等に対してページ移動を誤発火させない。
- エラー後も別の書籍を選べる。別の書籍を開いたときはページ位置を先頭に戻し、古い非同期応答を新しい書籍の表示へ適用しない。
- エラーは読み取り不能・破損・非対応・リソース欠落を分けて利用者へ案内する。読み込みとエラーの通知を支援技術から確認でき、キーボードのフォーカスが見える。
- 自動テスト・型チェック・ビルドが成功し、Windows の実アプリで標準ダイアログから表示・ページ送り・サイズ変更・別書籍の再選択まで確認する。
- Windows の確認ができない場合は、未検証の項目・理由・再実行方法を記録し、本単位の完了条件を満たしたとは扱わない。

### 実装方針

#### データの流れと境界

1. React の「書籍を開く」から Rust の書籍選択コマンドを呼ぶ。
2. Rust は標準ダイアログで選択されたファイルを読み込み、現在の書籍と識別子を管理する。選択キャンセルは正常な結果として返す。
3. React は書籍情報と最初の章を取得し、表示部品へ渡す。
4. 表示部品はアプリが管理する iframe 文書を生成し、本文内の相対参照を章パスから解決する。CSS 内の相対参照はCSS自身のパスから解決できるリソースURLを使用する。
5. ページ分割の準備後に本文を表示し、画像・CSS・サイズ変更による再配置後は本文中の位置から表示ページを決める。

Rust の通常関数で書籍セッションとリソース応答を検証し、OS ダイアログ・Tauri コマンド・専用プロトコルの登録は薄い境界にする。ファイル I/O はUIを止めない実行方式にする。専用プロトコルのURLは Windows と Linux の形式差を吸収する。

書籍切り替えは読み込み成功後に確定する。失敗時に以前の書籍の内容を新しいタイトルで表示しない。後続の章移動に備えて章を指定して取得できる形にするが、章移動UIは単位4で実装する。本文全体・画像をディスクへ展開する方式は採用せず、読書位置は実行中のみ保持する。再起動後の復元・読書履歴・表示設定の保存は後続計画で扱う。

#### 本文の分離とリソース制御

本文はアプリが生成する `srcdoc` を持つ iframe に配置し、書籍のHTMLをアプリ本体のDOMに直接挿入しない。書籍が持つ `base`・CSP・ナビゲーション指示等は採用せず、アプリ側で文書構造・参照先・CSPを管理する。

iframe の sandbox は本文スクリプト・フォーム・ポップアップ・親画面への移動を許可しない。アプリ側から本文のレイアウトを測れる構成とし、本文自身にはスクリプトの実行権限を与えない。CSP はローカル書籍のリソースと必要なインラインスタイルに限定する。書籍内のリンク操作はアプリ側で抑止し、目次・章内リンクの扱いは単位4で追加する。

書籍用のリソースURLは書籍識別子と正規化したアーカイブ内パスから組み立てる。URL の受信時のデコードと既存のパス処理の関係を確認し、二重デコードによる取り違えを防ぐ。レスポンスに正しい MIME を設定し、未知のパスを正常な空レスポンスとして返さない。

#### ページ分割と位置保持

固定高さの段組みを `column-fill: auto` で順に埋める方式を第一候補とする。表示幅・高さ・余白からページ寸法を決め、画像・ルビの改ページ制御を加える。本文内に大きな `min-height` や固定幅等があるケースは読書用スタイルで制約し、単に `overflow: hidden` で内容を捨てない。

ページ番号と本文中の位置を分離する。表示ページの先頭にあるテキストノードと文字位置、または画像等の要素を保持し、再配置後にその位置が属するページを再計測する。`ResizeObserver`、画像読み込み、フォント準備を再計測の契機とする。ブラウザAPIの利用方法は実装時に現行資料と照合する。

ページ送りは最初は即時切り替えとし、自動アニメーションを追加しない。実際の改ページ品質を優先する。ブラウザの段組みで対象書籍に欠落・重なりを解消できない場合は、表示方式を見直してユーザーに提示する。

#### 検証方法

小さな振る舞いごとに RED → GREEN → REFACTOR を実施し、意図した失敗理由と実行結果を記録する。OS操作をモックしたテストの成功を、標準ダイアログや実アプリ連携の成功として報告しない。

| 検証層 | 主な対象 | 実行方法 |
| --- | --- | --- |
| Rust 自動テスト | セッション、キャンセル結果、書籍切り替え、本文・リソース取得、エラー・パスの分類 | `cargo test --manifest-path src-tauri/Cargo.toml` |
| Rust チェック | コマンド登録・状態・依存関係の型と構成 | `cargo check --manifest-path src-tauri/Cargo.toml` |
| React・ロジック | IPC結果の扱い、状態遷移、ページ境界、キー操作、古い応答の除外 | `bun --no-env-file run test` |
| フロントエンドの型・ビルド | 本番への接続、表示部品、テスト用ページとの分離 | `bun --no-env-file run build` |
| 実ブラウザ | 改ページ、ルビ・画像、CSS、サイズ変更後の位置、文書の分離 | 単位3Bで `test:browser` を追加し、`bun --no-env-file run test:browser` で Chromium を実行 |
| Windows 実アプリ | 標準ファイル選択、専用URL、WebView2表示、前後・左右キー・再選択 | 下記の手動手順。実行環境と結果を記録 |

テスト用の書籍は自作し、正常な EPUB 2・3、長い章、ルビ入り、PNG・JPEG・GIF・CSS入り、不正・非対応・欠落リソースを含める。ブラウザ用のHTMLでは長い本文と大きい画像を用い、少なくとも3ページ以上になるケースでページ移動と最後までの表示を確認する。

テストは実際の入力・結果を観測し、欠落や重なり、違う章の読み取り、CSSの検査スキップ等があれば失敗するものにする。テスト自身の計算を期待値として丸写しせず、識別できる本文・画像とページ内の座標等から確認する。

`.env`・`.env.*` は読み込まない。Bun は `--no-env-file` を付け、既存の Vite・Vitest の `envDir: false` を維持する。Playwrightの設定や補助スクリプトでも秘密情報ファイルを読み込まない。

#### Windows の確認手順

1. 開発版またはビルドしたアプリを起動し、未選択の案内とキーボードのフォーカスを確認する。
2. 標準ファイル選択で自作 EPUB 2・3 を開き、タイトル・最初の章・ルビ・実際にデコードできる PNG・JPEG・GIF を確認する。
3. 長い章を前後ボタン・左右キーで最後まで読み、先頭・末尾で範囲外へ進まないことを確認する。本文iframeにフォーカスを移した状態でも操作する。
4. 表示領域を広げたり狭めたりし、読みかけの本文・画像の位置を保持し、本文に縦スクロールが必要にならないことを確認する。
5. 明色・暗色で本文と操作部の読みやすさを確認する。
6. ファイル選択のキャンセル、不正・非対応ファイル、欠落画像等のエラーと、その後の正常な書籍の再選択を確認する。
7. 書籍内のスクリプト・外部参照を含む自作データで、スクリプト実行・外部通信・アプリ操作が生じないことを確認する。

性能目標・配布形式・Windowsの対応バージョンは親計画で未決定のため、本計画で数値や対応保証を新たに設定しない。確認したOSとWebView2のバージョンは検証記録に残す。
