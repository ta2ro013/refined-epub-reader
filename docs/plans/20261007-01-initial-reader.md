# 初回の EPUB 読書機能の実装計画

- 計画承認日：2026-10-07。
- 状態：計画・単位1の開発開始承認済み。単位1の実装・検証と人間のレビューが完了し、PR 作成段階。単位2は未着手。
- 初回対象：Windows、横書きのリフロー型 EPUB。
- 各開発単位について個別に承認・実装・レビューを行う。

### 目的・背景

「洗練されたデザインで軽量な EPUB リーダー」というコンセプトの中心となる、ローカルの書籍を開いて読む体験を先に完成させる。現状は Tauri と React の初期テンプレートで、書籍読み込み・本文表示・章移動は未実装。フロントエンドのテストスクリプトも未整備である。

### 問題・解決方法

- 採用：1冊を開く、タイトル・本文を見る、目次・前後の章へ移動する、読み込み状態・エラーを確認する、別の書籍を開き直す、という一連の体験を初回の機能とする。製品の価値と表示品質を早期に検証できるため。
- 採用：Windows と横書きリフロー型 EPUB を先行する。ユーザーが選択した対象に検証を集中するため。
- 採用：ファイル操作、書籍処理、画面表示を分離する。Rust の書籍処理は OS 操作から切り離し、通常の関数として検証する。
- 棄却：初回から独自の EPUB 描画エンジンを構築する。対応範囲と検証負担が大きいため、既存ライブラリの適合性を評価して選定する。
- 後続：縦書き、固定レイアウト、本棚、検索、ブックマーク、読書位置の保存・復元、表示設定。読書位置の保存・復元、表示設定、本棚、ブックマーク・検索の順を推奨する。

### 完了条件（DoD）

- 合意した対応書籍を Windows のファイル選択から開き、タイトル・本文を表示できる。
- 目次と前の章・次の章の操作で移動でき、先頭・末尾で不正な移動が起きない。
- 読み込み中の状態と、破損・非対応ファイルのエラーを表示できる。
- エラー後も別の書籍を選択でき、開き直した書籍の内容が表示される。
- 正常な書籍、画像・ルビを含む書籍、破損・非対応書籍を使い、合意した対応範囲を検証する。画像・ルビの表示仕様は単位2着手前に確定する。
- 読み込み、タイトル・章順序・目次、章移動、エラー後の再読み込みを対象とする自動テストがすべて PASS する。
- JavaScript／TypeScript の変更後は `bun run test` と `bun run build` が成功する。
- Rust のコード・依存関係の変更後は `cargo check --manifest-path src-tauri/Cargo.toml` と `cargo test --manifest-path src-tauri/Cargo.toml` が成功する。
- Windows の実アプリでファイル選択、WebView での本文表示、章移動を確認する。モックでの成功だけを実アプリの確認として扱わない。
- 対象書籍、Windows の計測環境、読み込み時間・章移動の応答時間・メモリ使用量の目標を合意して記録し、その条件で検証する。
- 環境制約による未検証は理由と再実行方法を明示し、未検証のまま完了条件を満たしたとは扱わない。

### 実装方針

既存の Tauri、Rust、React、TypeScript、Bun を使用する。EPUB の解析・描画とファイル選択の依存関係は未選定であり、本番用依存関係の追加前に確認を求める。API・設定の調査時は Context7 で現在の公式ドキュメントを確認する。

基本のデータフローは、ファイル選択 → 書籍読み込み・解析 → タイトル・目次・章本文の取得 → 読書画面への表示とする。解析・描画ライブラリの選定に合わせ、Rust とフロントエンドの責務、IPC のデータ形式、画像等のリソース提供方式を具体化する。

既存の挨拶用デモ画面・コマンドは、読書機能に置き換える際に整理する。書籍内のスクリプト・外部通信、リソース参照、CSP・権限の扱いを本文表示の設計時に決める。

UI は読書画面のサンプルを提示してレビューし、合意した共通方針を `docs/FRONTEND_DESIGN.md` に記録する。サンプルは `docs/design/` に保存する。具体的な配色・書体は現在未決定である。

小さな振る舞いごとに RED → GREEN → REFACTOR を行う。設定・依存不足による失敗は RED と数えず、先にテスト環境を整備する。

- 開発依存関係として Vitest、jsdom、React Testing Library、user-event、jest-dom を追加した。本番用依存関係の追加はなし。
- `vitest.config.ts` に React の変換、DOM 環境、テストの対象、セットアップを設定し、`src/test/setup.ts` に DOM マッチャーとテスト後のクリーンアップを設定した。

- `bun --no-env-file run build`：TypeScript の型チェックと Vite ビルドが成功。
- `cargo check --manifest-path src-tauri/Cargo.toml`：成功。
- `cargo test --manifest-path src-tauri/Cargo.toml`：成功。ただし現時点の Rust テストは0件であり、書籍処理の検証は単位2で追加する。
