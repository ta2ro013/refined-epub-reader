### 目的・背景

横書きリフロー型 EPUB の読書画面を実装する前に、Rust でタイトル・目次・章本文・画像・CSS を取得できる基盤を作る。ファイル選択や WebView から切り離し、自作の書籍で読み込み処理を自動検証する。

### 問題・解決方法

- 採用：`epub` に EPUB の解析とリソース取得を任せる。独自の EPUB 解析器を作る負担を減らすため。
- 採用：`roxmltree` で EPUB 3 の Navigation Document やパッケージ情報の XML 解析を補う。`epub` の NCX 目次と EPUB 3 の Navigation Document は別扱いであるため。
- 採用：読書画面に依存しない書籍処理モジュールとデータ形式を用意する。読み込み処理と表示処理の検証を分離するため。
- 棄却：初回から独自の EPUB 描画エンジンを作る。対応範囲と検証負担が大きいため。
- 保留：EPUB.js の導入。Rust 側の解析と責務が重なるため、本文描画方式の決定時に再評価する。

### 完了条件（DoD）

- DRM のない EPUB 2・3 の横書きリフロー型書籍からタイトルと読み順を取得できる。
- EPUB 2 の NCX と EPUB 3 の Navigation Document の目次について、階層・相対パス・章内リンクを保持できる。
- 本文 XHTML を取得し、標準の `ruby`・`rt` を保持できる。
- 書籍内の PNG・JPEG・GIF と CSS を取得できる。ここではデータの取得を検証し、実際の表示と CSS の適用範囲は01の単位3で検証・決定する。
- 読み取り不能、破損、非対応を区別して返せる。リソース欠落も検証し、未取得を正常取得として扱わない。
- 縦書き・固定レイアウト・DRM・音声・動画は初回対象外とする。宣言や必要な内容から判定できる非対応要素を扱い、あらゆる書籍の互換性を保証するとはしない。
- 自作の EPUB 2・3、目次と読み順が異なる書籍、画像・ルビ入り、破損・非対応の書籍を使う自動テストがすべて PASS する。
- `cargo check --manifest-path src-tauri/Cargo.toml` と `cargo test --manifest-path src-tauri/Cargo.toml` が成功する。
- 既存のフロントエンドについて `bun --no-env-file run test` と `bun --no-env-file run build` が成功する。
- ファイル選択、IPC の実アプリ連携、Windows での表示、性能・配布確認は本単位の完了条件に含めず、親計画の後続単位で扱う。未実施の検証を成功と報告しない。

### 実装方針

- 本番用依存関係：`epub`、`roxmltree`。追加の承認は取得済み。具体的なバージョンは実装着手時に互換性を確認し、Cargo のロックファイルに記録する。
- Rust の書籍処理を `book.rs` に分離し、`lib.rs` からモジュールとして利用できるようにする。既存の初期画面・挨拶用コマンドはこの単位では置き換えない。
- 書籍情報、読み順、階層を持つ目次、本文 XHTML、リソースのパス・種別・内容を、後続の画面連携に利用できる形で扱う。
- 章本文・画像・CSS を必要に応じて取得できる構成を優先し、書籍全体の内容を毎回画面側へ送る前提にしない。
- 外部書籍の配布条件に依存しない自作テスト書籍を生成する。必要な ZIP 生成用の開発依存関係は `Cargo.toml` に記録する。
- 小さな振る舞いごとに RED → GREEN → REFACTOR を行う。設定や依存不足による失敗は RED と数えない。

### 実装・検証記録（2026-10-07）

- `Book::open` でローカル書籍を開き、`Book::from_reader` で通常の Reader から読み込める。タイトル、主たる読み順、階層付き目次を保持し、`chapter`・`resource` で内容を取得する。本文・画像・CSS 全体を起動時に画面側へ送る構成にはしていない。
- `TocEntry` はリンク先のパスとフラグメントを分離する。EPUB 3 のグループ見出しはリンクを持たないため、パスは `Option<String>` とした。アーカイブ内の相対パス・URI エンコードを解決し、Windows のパス区切りも `/` に統一する。
- `BookError` は `unreadable`、`invalid`、`unsupported`、`missing_resource` としてシリアライズできる。欠落リソースは取得時に通知する。本文の破損・CSS の縦書き宣言は章取得時に通知する。
- OPF の読み順を先に検証し、ライブラリが不正な参照を無視して一部の章だけを読み込むことを防いだ。目次のリンク先も manifest に存在することを確認する。
- 既知の固定レイアウト宣言、縦書き宣言、音声・動画のリソース、`EncryptedData` を含む暗号化宣言を非対応として返す。CSS は通常の `writing-mode`・接頭辞付き宣言を検出するものであり、CSS 全仕様の解析器や DRM の種類を網羅する検出器ではない。
- EPUB 2 の一般的な XHTML・NCX の DOCTYPE を受け入れる。外部 DTD の取得・外部実体の解決処理は登録していない。
- 画像のテストは PNG・JPEG・GIF の MIME とバイト列の取得を確認する。画像デコードや描画品質の検証は含まず、Windows の画面表示時に実画像を使って確認する。
- 本番用依存関係は `epub 2.1.5`・`roxmltree 0.21.1`。開発依存関係の `zip 6.0.0` でテスト時に書籍を生成する。バージョンは Cargo.lock に記録した。
- RED：タイトル・読み順、目次、本文・リソース、非対応判定、DOCTYPE・目次グループ、URI エンコード・不正な読み順の参照について、未実装の取得結果または検証不足を理由とする失敗を確認した。
- GREEN：各実装段階で関連するテストが成功した。レビュー修正後の Rust テストは22件すべて PASS。URI エンコードされた CSS パスについても取得失敗を再現して修正した。
- REFACTOR：リソースパスの正規化と XML 解析を共通処理に整理し、`cargo fmt` で整形した。整理後も全テストが成功した。
- `cargo check --manifest-path src-tauri/Cargo.toml`：成功。
- `cargo test --manifest-path src-tauri/Cargo.toml`：22件 PASS。
- `bun --no-env-file run test`：既存の2件 PASS。
- `bun --no-env-file run build`：型チェック・ビルド成功。
- `git diff --check`：成功。変更対象は予定どおり9ファイル。
- 検証環境は Linux。Windows の実アプリ、IPC、ファイル選択、本文・画像・ルビの表示、性能目標・配布は未検証であり、親計画の後続単位で実施する。

#### テストレビューの修正・検証

- 壊れた XHTML の namespace を維持し、閉じタグの欠落を単独で検証する fixture にした。
- Unicode パスの章を既存章と異なる本文にして、誤った章の読み取りを検出する。
- URI エンコードされた CSS パスについて、縦書き CSS を `Unsupported` とする対照テストを追加した。
- 実在する不正ファイルを `Book::open` で開き、`Invalid` と存在しないファイルの `Unreadable` を区別することを検証した。
- 一時コピーの書籍モジュールに4種類の不具合を個別に導入し、元のテストは成功し、修正後のテストは意図したアサーションで失敗することを確認した。本番コードには変異を加えていない。
- 修正後に Rust の22テスト、`cargo check`、テストファイルの整形チェックが成功した。追加のリファクタリングは不要と判断した。
- 人間が修正を確認・承認し、PR 作成を依頼した。
