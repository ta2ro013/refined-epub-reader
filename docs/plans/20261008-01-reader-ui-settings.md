### 目的・背景

2026-10-08 に採用した [UI サンプル](../design/ui-sample/README.md) を、まず既存の横書き読書画面に反映する。本文の読みやすさを保ち、紙・生成・夜のテーマと文字サイズ・書体を選択できるようにする。

ユーザーの「ではいったんコミットして、次の作業に入りましょう」を、直前に提示した第1段階（読書画面と表示設定）の計画を進める承認として扱い、詳細を本ファイルに整理した。2026-10-08、ユーザーの「OKです」により本計画の開発開始を承認済み。

### 問題・解決方法

- 採用：既存の Reader と PageView を拡張し、アプリの操作部と iframe 内の本文に同じテーマ・文字設定を適用する。現在の EPUB 読み込み、保護された本文表示、横書きページ分割を引き継ぐため。
- 採用：表示設定を独立した React コンポーネントにし、初期値を紙・19px・明朝にする。設定は今回の起動中だけ保持する。保存・復元仕様を今回の UI 変更に混在させないため。
- 採用：文字サイズ・書体変更で再組版するとき、ページ番号だけでなく現在の本文位置を基準に復元する。文字の大きさによってページ数が変わっても読み続けられるようにするため。
- 棄却：エクスポート HTML や付属の React ランタイムをアプリへ直接組み込む方式。モックのサンプルデータと実データが混在し、既存の安全な本文処理を利用できなくなるため。
- 今回の範囲外：本棚と本棚への遷移、目次・章移動、縦書き、検索、しおり、履歴・設定の永続化、読書時間の推定。これらは後続の小さい開発単位で扱う。未実装の操作や架空の進捗を利用可能な機能として表示しない。

### 完了条件（DoD）

- 操作部・本文・設定パネルがサンプルの配色・文字の階層・余白・角丸に沿う。既存の横書きで、左右の前後操作と下部の章内ページ位置を表示する。横書きでは左が前、右が次になる。
- 表示設定を開閉できる。紙・生成・夜、15・17・19・21・24・27pxの6段階、明朝・ゴシックを選択でき、操作部と本文へ反映される。
- 選択中の状態を視覚とアクセシビリティ属性で示す。文字サイズ上限・下限では該当操作が無効。設定パネルは Escape で閉じ、開いたボタンへフォーカスを戻せる。
- 設定・ウィンドウサイズ変更後に現在の本文位置を維持する。テーマ変更で本文リソースを再取得しない。
- 書籍選択、キャンセル、切り替え、読み込み・失敗通知、左右キー、ページ先頭・末尾の既存動作を維持する。ルビ・画像・書籍内 CSS の制限も維持する。
- 狭い画面で操作部・設定パネルを利用でき、本文や操作が切れないことをブラウザで確認する。
- 振る舞いの追加は TDD で実装し、全単体テスト・関連ブラウザテストが PASS。型チェック・本番ビルドが PASS。
- 3テーマの本文・補助文字・ボタン・フォーカスを確認する。Windows の Tauri 実機確認が利用できない場合は、その範囲を未検証として報告し、全環境での完了とは扱わない。

### 実装方針

- 既存の React・TypeScript・CSS とテスト環境を使用する。Rust・本番依存関係は変更しない。
- Reader が表示設定を管理し、設定パネルと PageView に渡す。PageView は iframe 内のテーマと本文設定を更新し、既存の位置アンカーによる再組版へつなぐ。
- 書体はサンプルにある名前と OS の代替書体を使用する。今回フォントの取得・同梱・外部通信は追加しない。指定フォントが未導入の環境では OS の代替書体になり、資料と完全には一致しないことを報告する。同梱は別の作業で検討する。
- アイコンが必要な箇所は提供された資料内の既存 SVG を再利用する。新しい SVG パスやライブラリは追加しない。仮名「栞 / SHIORI」を正式名称として実装しない。
- ユーザー向け進捗は現在取得できる章内のページ数を基準とする。全書籍ページ数や推定残り時間を生成しない。
- 変更対象は以下の最大10ファイルを想定する。追加が必要になった場合は作業単位を見直す。
