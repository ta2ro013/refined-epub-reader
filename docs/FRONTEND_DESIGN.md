# フロントエンドのデザイン方針

画面全体で共有する、ユーザーと合意したデザイン方針を記録する。
検討・サンプル提示・更新の進め方は、[フロントエンドのデザインルール](rules/frontend-design.md) に従う。

2026-10-07 に読書画面サンプルのデザインを承認した。以下はそのサンプルを基準とする共通方針であり、表示の実装・実機検証の完了を意味しない。

## 目的・デザインの方向性

横書きのリフロー型 EPUB は、縦スクロールを主操作にせず、画面に収まる本文を1ページずつ左右にめくる。読書中の操作を減らすため、ユーザーがこの方式を選択した。本文の読みやすさを優先し、操作部を控えめにする。配色・書体・操作部は下記のサンプルに沿う。

## 配色・テーマ

明色では外側の背景を `#f0f1f2`、本文面を `#fafafa`、文字を `#23282d`、補助文字を `#59636d` とする。アクセントは深緑 `#215e53`。本文と操作部に強い色差をつけず、ページを読むことに集中できる構成とする。

OS のテーマ設定に応じて暗色に切り替える。暗色では背景 `#20252a`、本文面 `#282e34`、文字 `#e8ecef`、補助文字 `#b4bec7`、アクセント `#9bd6c4`。明暗で同じ情報階層を保つ。

## 書体・文字サイズ

本文の既定値は明朝体20px、行間2。Windows の `Yu Mincho` を優先し、利用可能な明朝体へフォールバックする。見出しは30pxを基準とする。長文の読みやすさを優先し、ルビを保持する。

操作部は `Segoe UI`・`Yu Gothic UI`・`Meiryo` 等のOSのゴシック体、基本14px。本文と操作の役割を区別する。狭い画面では本文18px、見出し26pxを基準とする。書籍内CSSとの優先順位・適用範囲は本文表示の詳細計画で確定する。

## 余白・レイアウト・画面サイズへの対応

上部に書籍タイトルと「書籍を開く」、中央に本文、下部に章名・ページ位置・前後操作を置く。本文幅は最大36em、内側余白は32pxを基準とし、狭い画面では左右20pxへ調整する。

本文は1画面に収め、前後操作でページを切り替える。大きな画像は本文領域に収める。ウィンドウのサイズ変更時は本文中の読書位置を基準としてページを組み直す。具体的な最小ウィンドウサイズと改ページ品質は実装・Windows の実機検証で確認する。

## 共通コンポーネント・アイコン・操作状態

主要ボタンはアクセント色の塗りと6pxの角丸。「書籍を開く」はローカルの EPUB を選択する入口として上部に置く。前後操作は本文下部に置き、先頭・末尾では該当操作を無効にする。

未選択時は書籍選択への案内、読み込み中は本文準備の通知、失敗時は原因と再選択への案内を表示する。読み込み中は開く操作の重複を防ぐ。エラー文言は既存のエラー分類に対応させる。アイコンを追加する際のライブラリは未決定。

## アニメーション・アクセシビリティ

自動の装飾アニメーションは使わず、操作時の控えめなフィードバックを基本とする。ページ送りの動きの詳細は未決定。キーボードのフォーカスを明示し、前後ボタンと左右キーからページ移動できるようにする。

サンプルの本文・補助文字・主要ボタンの色は明暗ともにコントラスト比4.5:1以上を静的計算で確認した。実装時はキーボード操作、読み込み・エラー通知、ルビ・画像の表示、両テーマを実際の画面で確認する。

## 決定・変更の記録

採用した方針、理由、適用範囲、ユーザーとの合意内容を記録する。
共通方針を変更する場合は、影響する画面と、画面固有の例外も記録する。

- 2026-10-07：ユーザーは縦スクロールをなるべく避けたいと希望し、左右へのページ送りを選択した。前後ボタン・左右キーで移動し、サイズ変更時は読んでいた箇所を保つ方針。対象は横書きリフロー型の本文表示。配色・書体・新規依存関係の追加、詳細実装計画の承認は別途確認する。
- 2026-10-07：ユーザーは「書籍を開く」がローカルの EPUB を選ぶ入口であることを確認し、現在の画面デザインを承認した。サンプルの配色・書体・余白・操作部と状態表示を共通方針に反映した。新規依存関係の追加と詳細実装計画は、このデザイン承認には含めない。
