## 開発ルール

### 常に守ること

- 機能追加・振る舞いの変更・バグ修正は、原則として TDD（RED → GREEN → REFACTOR）で進める。
- 機能開発では、先に計画書ファイルを作成し、その計画書への人間レビューで承認を得てから開発を始める。この承認を開発開始の承認として扱う。開発後は人間のレビューを経てプルリクエストを作成する。
- 機能開発の変更対象が10ファイルを超える見込みの場合は、小さい開発単位に分割してユーザーに提示する。
- JavaScript／TypeScript（JSX／TSX を含む）を変更したら、`bun run test` を実行する。
- Rust のコードや依存関係を変更したら、対象の Cargo プロジェクトで `cargo check` と `cargo test` を実行する。`src-tauri` のプロジェクトでは、`--manifest-path src-tauri/Cargo.toml` を指定する。
- テスト、型チェック、ビルド、手動確認の結果を区別し、未実行の検証を成功したと報告しない。

### 依存関係とビルド

- フロントエンドの依存関係は Bun で管理し、インストールには `bun install`、追加には `bun add`、ビルドには `bun run build` を使う。
- Rust の依存関係は Cargo と `Cargo.toml` で管理し、ビルドには `cargo build` を使う。
- フロントエンド・Rust ともに、本番用の依存関係を新しく追加する前に確認を求める。
